How hard is finding a SHA-256 prefix?

The algorithm is simple. The work grows exponentially; parallel hardware makes each guess faster, not the math easier.

2. Why one more letter costs so much

Exact-case Base64, k characters: E[guesses] = 64k. For all-letter case-insensitive prefixes: E[guesses] = 32k. Digits, + and / still have a factor of 64.

4. Why memory stays small

For fixed-size, one-block candidates, total expected work is Θ(64k) exact-case (or Θ(32k) all-letter ignore-case). Ideal parallel elapsed time is approximately Θ(64k/P) with P effective workers, subject to overhead and hardware limits.

Working space is O(P·B) for P workers with batch size B; with fixed workers and batches it is O(1) in the number of guesses. Hashing a general input of length L takes O(L) time; our short-input fast path handles one SHA-256 block per guess.
